01 / BASICSNames, values, and variablesA variable is a name pointing at a value. That’s the useful mental model.OPEN +

Python doesn’t make you declare a variable before using one. Write a name, an equals sign, and the value you want to keep. Later, you can use the name instead of typing the value again. It sounds small, but naming things well is a big part of making code easy to read.

One detail that catches people at first: = means “store this value under this name,” not “these two things are mathematically equal.” Python works out the right-hand side first, then assigns the result. You can also give a new value to the same name later. The old value isn’t changed in place; the name now refers to the new one.

Names can use letters, numbers, and underscores, but they can’t begin with a number. By convention, Python variables use lowercase words with underscores, like total_price. Pick a name that gives the next reader a clue about what the value is for.

02 / BASICSStrings, numbers, and f-stringsEveryday values and a tidy way to put them into sentences.OPEN +

Strings are how Python represents text. You can write them with single or double quotes; choose whichever makes the sentence easiest to read. If your text itself contains a quote, the other quote style can save you from extra escaping.

Numbers behave a little differently depending on the operation. Adding two integers gives an integer, but ordinary division produces a float—even when the answer looks whole. Use // when you want whole-number division, and % when you want the remainder. Those two show up a lot when splitting items into groups or checking whether a number is even.

For sentences that include changing values, f-strings are usually the clearest option. Put an f before the opening quote and place each variable inside braces. You can put simple expressions there too, though keeping complicated logic on its own line makes the result easier to understand.

03 / COLLECTIONSLists and tuplesKeep values in order, then pick, change, or unpack them.OPEN +

A list is a good place for a group of things that belong together and may change over time. Lists keep their order, allow duplicates, and can hold different types, although in practice a list of similar items is often easier to work with.

Python starts counting positions at zero, so colors[0] means the first item. Negative indexes count back from the end: colors[-1] is the last item. A slice such as colors[1:3] starts at index 1 and stops before index 3. That “stop before” rule is the same one you’ll see in range().

Lists are mutable, which means methods like append() change the existing list. A tuple is ordered too, but it can’t have its items reassigned after it’s created. Tuples are useful for a small fixed group of related values, and unpacking lets you give those values readable names in one step.

04 / COLLECTIONSDictionaries, sets, and comprehensionsThree handy ways to organize or build a collection.OPEN +

When a list feels like the wrong shape for your data, a dictionary may fit better. It stores pairs: a key you look up and the value attached to it. A person’s name, settings for an app, or scores by player are all natural dictionary-shaped problems. Keys are unique, so assigning a value to an existing key replaces the old one.

Use get() when a key might be missing and you have a sensible fallback. Bracket lookup is fine when the key should definitely exist; if it doesn’t, Python raises a KeyError, which can help you spot a mistake rather than quietly hiding it.

A set keeps only unique values and is handy for removing duplicates or checking membership. Comprehensions are a compact way to build a collection from another one. They’re useful when the transformation is straightforward; if the expression starts to feel like a puzzle, a regular loop is kinder to the person reading it.

05 / CONTROL FLOWMake a choice with ifRun different code depending on what’s true.OPEN +

Programs get more useful when they can make a decision. An if statement checks a condition and runs its indented block only when that condition is true. Conditions can compare values, check whether a collection is empty, or combine smaller checks with and, or, and not.

Python checks branches from top to bottom. Once one condition matches, its block runs and the rest of that chain is skipped. That means the order matters: put the more specific cases first, then use else for the catch-all. You don’t need an else if there’s nothing useful to do when the condition is false.

Indentation isn’t decoration in Python; it defines the block. Keep the same indentation within a branch, usually four spaces. In the example, a score of 82 fails the first check and passes the second, so grade becomes "B".

06 / CONTROL FLOWLoops: for, while, and when to stopRepeat a small bit of work without repeating yourself.OPEN +

A loop is useful when you want the same operation applied to several values. A for loop takes each item from an iterable in turn, so it works with lists, strings, dictionaries, files, and plenty more. Most of the time, loop over the values directly instead of counting indexes by hand.

range() is there when you really do need a sequence of numbers. Its stop value is not included, which is why range(5) gives you 0 through 4. If you need both a position and an item, enumerate() provides them together without extra bookkeeping.

A while loop repeats as long as its condition remains true. Make sure something in the loop can eventually change that condition, or it may never stop. break exits the loop; continue skips the rest of the current pass and moves on to the next item.

for number, item in enumerate(["tea", "coffee"], start=1):
    print(number, item)
07 / FUNCTIONSFunctions, arguments, and return valuesGive a useful bit of code a name you can call again.OPEN +

Functions let you give a chunk of work a name, then call it wherever you need it. Start with def, choose a clear name, and put any inputs in parentheses. The indented body runs when the function is called—not when Python first reads the definition.

A function can send a result back with return. That’s different from print(): printing shows something to a person, while returning makes a value available to the rest of your program. If a function reaches the end without a return statement, Python returns None.

Arguments can be passed by position or by name. Named arguments can make a call easier to scan, especially when there are several options. Defaults are useful for inputs that have a common value, but avoid using a mutable list or dictionary as a default; that same object would be reused between calls. *args and **kwargs collect extra positional and keyword arguments when a function needs that flexibility.

08 / FUNCTIONS & OBJECTSClasses and objectsBundle data and the behavior that belongs with it.OPEN +

Classes are a way to describe objects that share a shape and behavior. If a program has several dogs, for example, each dog can have its own name while sharing the same speak() method. The class is the description; each dog you create from it is an instance.

When Python creates a new instance, it calls __init__. The first parameter is conventionally named self; it refers to the particular instance being set up. Writing self.name = name stores the incoming value on that object, so a different dog can have a different name.

Methods are functions that belong to a class, and attributes are values attached to an object. You don’t need a class for every bit of data—sometimes a dictionary or a few plain functions are simpler. Classes become useful when values and the operations that work on them naturally belong together. Inheritance can share or specialize behavior, but composition is often a simpler first choice.

09 / CONTROL FLOWErrors and exceptionsHandle expected problems, and use tracebacks to find the rest.OPEN +

An exception is Python’s way of telling you that something went wrong while the program was running—maybe text wasn’t a valid number, a file wasn’t there, or a key was missing. The traceback shows where the error traveled through your code. Start at the last line to see the exception type and message, then look above it for the line that triggered it.

Use try around the small operation that might fail, and catch a specific exception when you know how to respond. Catching every possible exception can hide unrelated bugs, so it’s better to handle the case you actually expect. If the input is bad, for example, you might show a useful message or choose a safe fallback.

The optional else block runs only when the try block succeeds. finally runs either way and is commonly used for cleanup. For files, a with block usually handles cleanup for you, so you won’t need to write a finally just to close one.

PartJob

exceptHandle a matching exception
elseRun if no exception happened
finallyRun whether or not it failed
try:
    count = int("12")
except ValueError:
    count = 0
10 / MODULES & TOOLSImports, files, and JSONUse the standard library instead of rebuilding common tools.OPEN +

Python’s standard library comes with tools for everyday jobs, so it’s worth checking what’s already available before writing your own. An import brings a module or a specific name into the current file. For example, from pathlib import Path gives you a handy object for building and working with file paths.

Paths are not always just strings: folders and separators vary between operating systems. pathlib handles those details and gives you readable methods such as read_text(). Specify an encoding like UTF-8 when reading text so the file is interpreted consistently.

JSON is a common format for data exchanged between programs. The json module converts JSON text into Python values with loads(), and converts Python values back to JSON text with dumps(). A with block is a reliable way to work with an open file because it closes the file when the block ends, even if something goes wrong inside it.

11 / MODULES & TOOLSTesting and virtual environmentsCheck your assumptions and keep project dependencies tidy.OPEN +

Tests are small checks that help you catch mistakes before they become confusing. An assert is the simplest version: it states what you expect to be true, and raises an error if the result is different. It’s useful while developing, but don’t use assertions to validate important user input—Python can disable them in optimized mode.

As a project grows, give tests their own structure. The standard-library unittest module lets you group related checks into test cases and run them together. A good test focuses on one behavior and uses a name that explains what should happen. When a test fails, treat it as a clue: inspect the actual value and compare it with the expectation.

Virtual environments solve a different everyday problem. Projects can depend on different versions of libraries, and installing everything globally can turn into a mess. Keeping each project’s packages isolated makes it easier to reproduce the setup later. Python’s standard library is enough for the examples here; environments matter when your project uses additional packages.

12 / MORE PYTHONGenerators, decorators, and context managersSmall tools for lazy work and reusable behavior.OPEN +

These tools make more sense once you’ve run into a problem they solve, so there’s no need to memorize them on day one. A generator is a function that uses yield to produce values one at a time. Rather than building a whole list up front, it can pause after each value and continue when the next one is requested. That’s useful for long sequences or data you want to process as it arrives.

A decorator is a function that takes another function and returns a wrapped version. The @ syntax applies the decorator when the function is defined. Decorators show up in web frameworks, logging, and timing tools, but they’re still just a way to reuse behavior around a function call.

Context managers handle a beginning-and-end pattern: set something up, run a block, then clean up. The familiar with open(...) form is an example. Type hints, meanwhile, annotate what kinds of values a function expects or returns. Python doesn’t enforce most hints at runtime, but editors and other tools can use them to catch misunderstandings early.

FeatureLook forCommon use
GeneratoryieldProduce values as needed
Decorator@somethingAdd behavior around a function

def count_up_to(limit):
    for number in range(limit):
        yield number

for number in count_up_to(3):
    print(number)
13 / MORE PYTHONAsync, useful built-ins, and what to learn nextA quick map of a few ideas you’ll meet as projects grow.OPEN +

Once you know the basics, a few built-ins can make everyday code shorter without making it harder to read. len() counts items, sorted() returns a new sorted list, and zip() walks through several iterables side by side. any() and all() answer useful yes-or-no questions about a group of values.

Async Python is for work that spends time waiting—often network or file I/O—where it can be helpful to let other tasks make progress in the meantime. It doesn’t automatically make CPU-heavy work faster, and it does add concepts to think about. You’ll see async def define a coroutine and await pause it until an asynchronous operation is ready.

There isn’t one checklist you have to finish before you’re allowed to build something. Pick a small project, look up the built-ins that solve the next problem, and learn a feature when it becomes useful. Reading error messages and making tiny experiments are part of learning Python, not signs that you’re doing it wrong.
